システム開発仕様書（AI指示用）

あなたは優秀なフルスタックエンジニア兼SEOスペシャリストです。
以下の仕様に従って、システムの設計およびコード生成を行ってください。

0. 最重要目標（Tier 1）

本プロジェクトの絶対的なTier 1の目的は、Google検索において「mdファイル変換」というキーワードでSEO 1位を獲得することです。

以降のすべての設計、技術選定、UI/UX、コーディングは、この目標を達成するために最適化されている必要があります。AIであるあなたは、SEOの観点（Core Web Vitalsのスコア最大化、セマンティックなHTML構造、メタデータの最適化、SSR/SSGによる初期ロードの高速化など）を常に最優先して提案・実装してください。

0.5. 開発の動機と原点（Core Motivation）

なぜ「Markdown変換」ではなく「mdファイル変換」を狙ったのか？
世の中にはすでに「Markdown変換ツール」は多数存在しています。しかし、開発者の原体験として**「テキストやCSVデータがある時、わざわざ重いIDE（VSCodeなど）を開いてコピペし、拡張子を.mdにして保存する作業がとにかくダルい（面倒くさい）」**という強烈なペインがありました。

つまりこのツールは、「Markdownという記法を学びたい人」以上に、**「今すぐ手元にあるごちゃごちゃしたテキストを、パッと『mdファイル』という実体にしてサクッとダウンロードしたいだけの人」**を最重要ターゲットとしています。この原点をUI/UXやコピーライティングに常に反映させてください。

1. SEO戦略からの逆算（理想のアーキテクチャ）

「mdファイル変換」で検索するユーザーは「今すぐ、無料で、安全に、手軽に変換したい」という意図を持っています。これを満たし、SEO評価を最大化するための理想形は以下の通りです。

圧倒的な表示速度 (Core Web Vitals極化): サーバーとの通信（ラウンドトリップ）を極力排除し、完全な静的サイト（SSG）としてエッジから配信する。

プライバシーと安全性: ユーザーのデータをサーバーに送信せず、すべてブラウザ上（クライアントサイド）で変換処理を完結させる。

直帰率の低下（滞在時間の向上）: ページ遷移なしで即座に結果が分かるUI（リアルタイムプレビュー）。

網羅的なSEOコンテンツ: ツールだけでなく、検索エンジンに評価されるテキスト（使い方、Markdownのメリット、FAQ構造化データ）を同一ページ内に適切に配置する。

2. 実装スコープ（MVPと妥協点）

上記の理想を踏まえつつ、初期リリース（MVP）ではコストと開発スピードの観点から以下の通りスコープを絞ります。

【MVP対象（今回実装するもの）】

テキスト貼り付けからのmdファイル化

エディタエリアにテキスト（プレーンテキストやHTML等）を貼り付け、即座にMarkdownに変換する機能。

軽量なテキスト系ファイルのアップロード＆mdファイル化

処理が軽いファイル（.txt, .html, .csvなど）をドラッグ＆ドロップで読み込み、Markdownに変換する機能。

※これらはすべてブラウザ（クライアントサイド）で処理し、サーバーコストをゼロにする。

【MVP対象外（将来の拡張機能・妥協点）】

処理が重く、複雑なパース処理や外部API連携が必要なファイル（.docx, .pdf, 画像からのOCR抽出など）の変換機能は今回は実装しない。

3. 技術スタック

SEO1位と完全クライアントサイド処理を実現するための技術構成です。

フロントエンド・フレームワーク: Next.js 14以上 (App Router), React, TypeScript

レンダリング方式: SSG (Static Site Generation) - Vercel等のEdge Networkで配信

スタイリング: Tailwind CSS, shadcn/ui (必要最小限のコンポーネントのみ使用しバンドルサイズを抑える)

変換ロジック: turndown (HTML to MD) などの軽量な純JSライブラリを使用。

インフラ/デプロイ: Vercel または Cloudflare Pages

データベース/バックエンドAPI: なし（不要）。すべてブラウザ上で完結させる。

4. 機能要件

リアルタイム変換エディタ

左ペインに入力（テキスト貼り付け）、右ペインにMarkdownのプレビューとソースコードがリアルタイム表示されるUI。

ファイルアップロード（ドラッグ＆ドロップ）機能

対象拡張子: .txt, .html, .csv

File APIを使用してブラウザのメモリ上に読み込み、即座に変換処理にかける。

エクスポート機能

「.mdファイルとしてダウンロード」ボタン（Blob APIを使用してブラウザ上でファイル生成）。

「クリップボードにコピー」ボタン。

SEO最適化コンテンツエリア（Below the fold）

ツール下部に、SEO目的のコンテンツ（H2, H3タグを用いたセマンティックな構造）。

例：「mdファイル変換ツールの使い方」「対応しているファイル形式」「よくある質問（FAQ構造化データをJSON-LDで埋め込む）」。

5. 画面構成（ルーティング）

/ : トップページのみのシングルページ構成。

First View（ファーストビュー）にツール本体を配置し、ユーザーが迷わず使えるようにする。

スクロールした下部に、SEO用の解説テキストやFAQを配置する。

6. コーディングルール・制約事項（SEO特化型）

ゼロ・サーバー通信: 変換処理のためにバックエンドAPI（/api/convertなど）を作らないこと。すべてブラウザのJS内で処理する。

SEO第一主義: HTMLのタグ（<main>, <article>, <section>, <h1>, <h2>等）は検索エンジンが理解しやすいセマンティックな構造で記述すること。

メタデータの徹底: Next.jsの generateMetadata を使用し、title, description, OGP, canonical URLを適切に設定すること。

パフォーマンス: Lighthouseのスコアで全項目（特にPerformanceとSEO）95点以上を獲得できるコードを出力すること。不要な重いライブラリは導入しない。

型安全: TypeScriptの型推論を活用し、any 型は絶対に使用しないこと。

8.  （追加仕様）細かい依頼
    8-1. 内部リンク評価（リンクジュース）の分散
    ヘッダーやメインメニューなどの目立つ場所にライセンスページのリンクを置くと、一番評価を高めたい「トップページ（ツール本体）」に向かうべきSEOの評価が分散してしまいます。
    対策: リンクは必ず「フッター（ページ最下部）」の目立たない位置に配置してください。

        8-2. 重複コンテンツのリスク（非常に軽微）

    オープンソースのライセンス文や、他サイトを参考にした定型的な利用規約は、テキストが完全に他サイトと一致します。Googleは法的な定型文であることを理解しているためペナルティ対象になることは稀ですが、サイト全体の「独自性」の割合を下げる要因にはなります。
    対策: 検索結果に表示させる必要がないページなので、ライセンスページには <meta name="robots" content="noindex"> を設定し、Googleのインデックスから除外するのが最も安全で確実な手法です。
